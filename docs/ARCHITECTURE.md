# 技术架构与维护规范

## 1. 架构原则

本项目采用零构建、零运行时依赖的静态 Web 架构。原因是展厅环境必须支持断网运行，并允许工作人员直接双击 `index.html` 启动。

引入框架或模块打包器必须同时满足以下条件：

1. 发布结果仍可通过 `file://` 协议运行；
2. 不依赖远程资源；
3. 不降低手柄、鼠标与触屏兼容性；
4. 仓库中保留可直接运行的发布入口。

账号系统同样是本机实现：不做任何网络请求，口令以「盐 + 哈希」形式存在 `localStorage`。它只用于区分访客与延续个人成绩，**不构成安全边界**，不能存放真实密码。

## 2. 运行状态

游戏使用显式状态机组织页面流程：

```text
STORY → LOGIN → MODE → SCHEME → TUTORIAL_ASK → DIFFICULTY → READY → COUNTDOWN → PLAY → RESULT
                     ↘ (键盘 / 手柄跳过 SCHEME)         ↘ TUTORIAL_DONE
                            TUTORIAL（PLAY 的脚本化分支）
```

- `STORY`：四幕剧情及积分说明。
- `LOGIN`：登录、注册与本机名册快速登录。
- `MODE`：键盘 / 手柄 / 鼠标 / 触屏四选一。
- `SCHEME`：仅鼠标与触屏进入，选择点按手感。
- `TUTORIAL_ASK`：首次登录且教程未完成时询问一次。
- `DIFFICULTY`：四档难度。
- `READY`：当前模式的两步说明与「开始」。
- `COUNTDOWN`：三秒倒数。
- `PLAY`：严格 60 秒游戏循环；`tutorialOn` 为真时改走 `tutorialUpdate()`。
- `RESULT`：结算、四端榜单与文物考据卡。
- `TUTORIAL_DONE`：教程完成弹层。

有「记住我」会话时，启动直接进入 `MODE`，跳过剧情与登录。新增页面阶段时必须加入状态机，禁止依靠多个无关布尔变量拼接流程。

## 3. 输入规范

业务逻辑只识别统一动作：

- `LEFT`
- `RIGHT`
- `A`（敲鼓）
- `START`
- `BACK`

键盘、Gamepad API 与指针输入仅负责映射为统一动作，玩法逻辑不得直接判断具体物理键位。

- 键盘始终可用，作为其它模式的兜底输入。
- 手柄左摇杆采用七槽位吸附：`Math.atan2()` 取方向后选择角距离最近的槽位，并保留滞后避免抖动。
- 鼠标 / 触屏把一次点按折算成约 140ms 的 `A` 按下窗口（`pointerPressUntil`），从而复用同一套敲鼓判定与连打计数。
- 触屏三种手感：
  - `tap`：点铜马＝对准＋敲鼓；
  - `twoStep`：点铜马只对准，点铜鼓或大鼓按钮才敲；
  - `drag`：在赛场上按下并拖动，`angle` 直接跟随指针角度连续旋转。
- 主尊训斥与双虎阶段忽略手感差异，任何点按都计为敲鼓，保证连打可用。
- 指针模式下铜马会有 1.68 倍隐形热区（`.hitPad`），保证手指点得中。
- 鼠标模式不显示「敲鼓」大按钮；触屏仅在两步/滑动手感或主尊、双虎连打阶段显示（`updateDrumPad()`）。
- 光标全程可见：`body` 为 `default`，可点元素为 `pointer`；鼠标模式下赛场也保持标准箭头，不换成准星。
- 视口不再隐藏鼠标指针；鼠标模式赛场用 `crosshair`、铜马用 `pointer`，避免玩家找不到光标。

## 4. 时间与计分

- 一局时长以 `performance.now()` 为唯一时间源。
- 动画帧只负责轮询与渲染，不允许用帧数推算游戏时间。
- 分数最低为 0。
- 排行榜键名为 `gudian_leaderboard_v2`，记录带 `mode` 字段，四端各保留 20 条，结算展示前 5 条。
- 同一账号在同一操控端只保留历史最高分；旧版无 `mode` 的记录迁移后统一归入 `keyboard`。
- 账号键名为 `gudian_accounts_v2`，`best` 字段保存四端最高分，用于解锁「万贝狂潮」。

## 5. 素材规范

- 所有运行素材放入 `assets/`。
- 图片使用小写 kebab-case 文件名。
- HTML 中只能使用相对路径。
- 禁止 Base64 内联大图或引用远程 URL。
- 铜马为内联 SVG 剪影（`HORSE_SVG`），不得退回文字圆点；马身随槽位角度朝外，目标亮起时由 `runOut` 向外围冲刺。
- 缰绳 `.tether` 与马圈 `.ring` 在目标激活时进入赤红警告态，这是玩法的核心视觉反馈。
- 历史导出包归档到 `archive/`，不得作为运行时依赖。

## 6. 账号与隐私

- 玩家账号、口令哈希与成绩仅写入浏览器本地存储。
- 不进行网络请求，不上传任何数据。
- 口令使用随机盐 + 非加密散列，仅能防止明文直读；不得描述为“安全加密”。
- 游戏名通过 `textContent` 或 `esc()` 渲染，禁止直接拼接未转义的用户输入。
- 本机名册最多 24 个账号；账号面板支持改口令、退出登录与删除本机账号（同时清理该账号的榜单记录）。

## 7. 新手教程

- 教程是 `PLAY` 的脚本化分支，复用同一套 `spawnTarget` / `handleHorse` / `beginScold` / `beginTiger`，通过 `tutorialOn` 与 `tutorialStep` 控制节奏。
- 教程固定使用 `easy` 规则：不扣分、目标不超时、训斥与双虎必定通过。
- 第 1 步（对准）必须屏蔽敲鼓，否则「点马即敲」会把对准与敲击合并，吞掉按键边沿。
- 教程结束不写榜单，只把账号的 `tutorialDone` 置为真。

## 8. 音频规范

- 背景音乐与反馈音效使用 Web Audio 在本地实时合成，不依赖远程音频。
- 每局开始时创建氛围声部，结算时必须淡出并释放振荡器与定时器，禁止多局叠音。
- 背景音乐保持低音量，奖励、惩罚、主尊训斥和双虎事件音效拥有更高反馈优先级。
- 首次播放必须由指针或键盘用户手势解除浏览器自动播放限制；界面必须明确显示当前音频上下文是否已经运行。
- 主尊 QTE 使用 `scold.hits` 计数，禁止退回单一 `held.A` 按住判定；贝潮连锁使用时间窗计数并在成功后清零。
- 手柄所有离散动作统一经过全局短震反馈，业务事件可在此基础上叠加奖励、惩罚或事件震动。

## 9. 响应式与触屏

- 画面基准为 16:9，使用 `min(100vw, 177.78vh)` 缩放；竖屏触屏设备显示「请把设备横过来」，可手动选择继续竖屏。
- `body` 使用 `touch-action: none` 与 `overscroll-behavior: none`，避免移动端滚动与下拉刷新。
- 宽度小于 900px 时隐藏左右词条栏，赛场占满整行（网格必须是 `1fr`，不能让赛场落进 0 宽列）。
- `#discWrap` 以高度约束（`height: 94%` + `aspect-ratio: 1`）保证短屏也能完整看到器盖。
- 触屏可点元素最小高度 32～42px；铜马另有隐形热区。
- `#drumPad` 只服务触屏：`updateDrumPad()` 在 `begin / beginScold / beginTiger / 结算` 时重算，点马即敲手感仅在连打阶段出现，鼠标与手柄不显示。

## 10. 发布检查清单

- 游戏标题严格为《器盖上的复活夜：古滇万贝迷踪》。
- 直接双击 `index.html` 可以运行。
- 断网状态下四张图片正常显示。
- 键盘、手柄、鼠标、触屏四种模式各能完成一局，且成绩分别进入对应榜单。
- 旧版数据首次打开时自动迁移为账号与键盘榜记录。
- 倒计时严格在 60 秒结束。
- 登录、注册、游客试玩、切换账号、修改口令均可用。
- 新手教程五步可走完并可跳过，完成后不再自动询问。
- 通告未读红点在阅读后消失。
- 浏览器控制台无错误。
- `npm run check` 通过。
