# 技术架构与维护规范

## 1. 架构原则

本项目采用零构建、零运行时依赖的静态 Web 架构。原因是展厅环境必须支持断网运行，并允许工作人员直接双击 `index.html` 启动。

引入框架或模块打包器必须同时满足以下条件：

1. 发布结果仍可通过 `file://` 协议运行；
2. 不依赖远程资源；
3. 不降低手柄兼容性；
4. 仓库中保留可直接运行的发布入口。

## 2. 运行状态

游戏使用显式状态机组织页面流程：

```text
STORY → NAME → MODE → READY → COUNTDOWN → PLAY → RESULT
```

- `STORY`：四幕剧情及积分说明。
- `NAME`：登记守器人姓名。
- `MODE`：选择键盘或手柄。
- `READY`：展示当前模式的两键说明。
- `COUNTDOWN`：三秒倒数。
- `PLAY`：严格 60 秒游戏循环。
- `RESULT`：结算、本机排行榜与文物考据卡。

新增页面阶段时，必须加入状态机，禁止依靠多个无关布尔变量拼接流程。

## 3. 输入规范

业务逻辑只识别统一动作：

- `LEFT`
- `RIGHT`
- `A`（敲鼓）
- `START`
- `BACK`

键盘与 Gamepad API 仅负责映射为统一动作。玩法逻辑不得直接判断具体物理键位。

左摇杆采用七槽位吸附：先通过 `Math.atan2()` 取得 360° 方向，再选择角距离最近的铜马槽位，并保留少量边界滞后以避免摇杆在两个槽位间抖动。渲染箭头必须始终落在某个槽位中心。

## 4. 时间与计分

- 一局时长以 `performance.now()` 为唯一时间源。
- 动画帧只负责轮询与渲染，不允许用帧数推算游戏时间。
- 分数最低为 0。
- 排行榜键名为 `gudian_leaderboard`，最多保存 20 条，结算展示前 5 条。
- 玩家姓名键名为 `gudian_last_player`，最长 12 个字符。

## 5. 素材规范

- 所有运行素材放入 `assets/`。
- 图片使用小写 kebab-case 文件名。
- HTML 中只能使用相对路径。
- 禁止 Base64 内联大图或引用远程 URL。
- 历史导出包归档到 `archive/`，不得作为运行时依赖。

## 6. 安全与隐私

- 玩家姓名和成绩仅写入浏览器本地存储。
- 不进行网络请求，不上传任何数据。
- 姓名通过 `textContent` 渲染，禁止作为 HTML 注入。

## 7. 发布检查清单

- 游戏标题严格为《器盖上的复活夜：古滇万贝迷踪》。
- 直接双击 `index.html` 可以运行。
- 断网状态下四张图片正常显示。
- 键盘和手柄模式可分别完成一局。
- 倒计时严格在 60 秒结束。
- 姓名登记和排行榜可在刷新后保留。
- 浏览器控制台无错误。
- `npm run check` 通过。
